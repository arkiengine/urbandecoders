At a glance

What it takes, what you get.

It takes

A live Revit model or schedule exports, plus the specification and a measurement standard

You get

A quantity register as the audit layer, work-section tabs in the standard's own order with spec wording and source element IDs on every line, Rate and £ columns left empty, an exclusions list, and a numbered query sheet for the QS.

Quick reference

How to run it.

Model quantities plus a specification become an auditable draft takeoff — a measuring register a QS can check, not a bill you can tender on. Every line traces to source Element IDs. Every gap, guess and convention is tagged rather than silently absorbed. No rates, no prices, ever.

Run it

Connect Revit (or attach the schedule exports) with the specification:

BoQ takeoff from this model — spec attached, NRM2.
Quantify this model for the QS. We only have the schedule exports.
Material takeoff for the cost plan — which units does NRM2 want?
Bill of quantities for plot 1. Spec is the Meadow Lane outline.
Run the worked example so I can see what it does.

Say the phase and design option being measured — mixed phases double-count silently. With no live connection and no exports, it still builds the workbook structure with empty quantity columns, as a measuring list.

The workbook

TabWhat it holds
Cover & BasisProject, model filename, phase and option measured, extraction date, MCP server and tool used, measurement standard, units — and in bold: DRAFT TAKEOFF FOR VERIFICATION — NOT FOR TENDER. Then the exclusions and assumptions list in full.
Quantity RegisterThe raw extract, one row per element or type: Element ID, UniqueId / IFC GUID, category, family, type, level, phase, count, length, area, volume, materials, key parameters, and a Source column naming the tool call that produced it. Untouched by mapping logic — this is the audit layer.
Work sectionsOne tab per work section (NRM2 order by default): Ref · Description in the spec's own wording · Spec clause · Unit · Qty · Rate · £ · Source Element IDs · Notes / Tags. Rate and £ present and empty. Qty cells reference the register by formula where practical, so the trail stays live.
Queries for QSEvery tagged line collected as a numbered query list. Usually the most valuable sheet in the file.

Tags: [to verify] · [assumed: …] · [not modelled] · [not in spec] · [check — implausible value] · [to verify — spec/model conflict].

The pre-flight that saves the takeoff

Model faults become quantity faults. Six things corrupt counts and areas before any BoQ logic runs, and none of them announce themselves in a schedule.

Identical instances in the same place (duplicates double-count) · duplicate or empty Marks (the trail to the door and window schedules) · links — elements in linked RVT or IFC are not in host schedules, so they are [not measured — linked] and never mixed in silently · groups and nested shared families counted once each · in-place families, which usually carry no Assembly Code and report one lumped volume · curtain walls, where panels and mullions are separate categories and the host wall area must not be measured again on top. Missing Assembly Codes or inconsistent type naming is the single biggest accuracy risk — it is reported as a finding, not a footnote. Where a revit-model-audit report exists, its findings are reused.

What it will not do — by design

  • Attach a rate, a price or a cost, even casually. Pricing sits with the QS; the columns stay blank.
  • Invent an allowance. No waste percentages, no laps, no "add 10%". Formwork, temporary works, scaffolding, builder's work and commissioning appear as prompts with the quantity blank.
  • Reconcile spec against model. 140 mm in the spec and 100 mm in the wall type both get quoted, at the modelled quantity, tagged as a conflict.
  • Measure in the unit Revit happens to give where the standard wants another. The conversion basis goes in the Notes column.
  • Correct an implausible value. A 2,000 m³ door is tagged, not fixed.
  • Touch the model. No transactions, no colour splash, no purge, no save, no sync. A takeoff that changes what it measures cannot be audited.
  • Claim compliance with a measurement standard. Clauses applied are cited and tagged [to verify].
  • Answer access questions — those go to part-m-revit-check.

Work the output

  1. Read the Cover tab's exclusions before the quantities. What is missing shapes the number more than what is there.
  2. Work the Queries tab with the design team first. It is the list that decides how much of the takeoff survives.
  3. Fix model hygiene in the model, then re-extract. Patching quantities in the spreadsheet breaks the audit trail you just paid for.
  4. Spot-check ten lines by Element ID with Select by ID in Revit. If they reconcile, the register is doing its job.
  5. Hand it to the QS as a draft with the standard named. Only their review can answer whether it is accurate enough to tender.
  6. For a formal cost plan, cross-check against a Revit-native material takeoff schedule — two independent extractions catch each other's errors.

Remember: a model gives net modelled quantities. A bill contains judgement the model cannot supply. This closes the first gap and names the second.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

revit-boq-takeoff

Turn Revit model data (via a Revit MCP connection, or exported schedules) plus a specification into a draft Bill of Quantities takeoff — an editable .xlsx quantity register mapped to spec clauses, structured to a stated measurement standard (NRM2 default), every line traceable to source element IDs, every assumption tagged [to verify], [assumed], [not modelled] or [not in spec]. A draft takeoff and query sheet for a QS to check — never a tender-ready BoQ, never a cost estimate. Use this WHENEVER someone asks for a "BoQ", "bill of quantities", "quantity takeoff", "material takeoff", "quantify this model", "quantities for the QS", "cost plan quantities", "NRM2 takeoff", "schedule of quantities", or wants quantities pulled from Revit/BIM via MCP and matched to a spec — even with only a schedule export, no live connection. Do NOT use for pricing, rates or cost advice (quantities only), nor for access reviews (part-m-drawing-check, part-m-revit-check) or model health (revit-model-audit).
