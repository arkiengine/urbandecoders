Install

Install just this one.

Two routes. Both end with Claude loading the skill by itself when your conversation matches.

A Claude app, Chat or Cowork

  1. Download nano-banana-prompt-builder.skill below.
  2. Open Claude, go to Settings → Capabilities → Skills and upload the file.
  3. Start a conversation and attach your material. The skill loads itself on a match.
nano-banana-prompt-builder.skill · 11.3 KB

B Claude Code, in your project

Unzip the package into your skills folder, then restart Claude Code.

mkdir -p .claude/skills && unzip nano-banana-prompt-builder.skill -d .claude/skills/

Use ~/.claude/skills/ instead to install it for every project.

Quick reference

How to run it.

Turns a rough image idea, or a source image plus scribbled instructions, into a copy-paste Nano Banana / Gemini prompt for architectural visualisation — exteriors, interiors, masterplans, diagrams, model shots — with the lock and negative blocks that stop the model redesigning the scheme. A prompt engineer, not an image generator, and never a designer.

Run it

Paste the idea, or attach the source image and your notes, then ask:

Write me a Nano Banana prompt for this.
Turn this Enscape screenshot into a photoreal image — same geometry.        (transform)
Image 1 is my model, Image 2 is the brick I want — write the prompt.        (composite)
It keeps warping the geometry / it looks like a movie — fix my prompt.      (repair)
Diagram, not a render: flat axonometric, three labels.                      (non-photoreal)
No questions, use defaults.                                                 (skips the interview)

Expect 4–7 questions back before the prompt. That is the skill working: the alternative is a beautiful render of a building you did not design.

The deliverable

PartWhat it holds
Final promptCopy-paste code block. Subject → design language → technical specs, in that word order. Staged edits get one block per stage.
Lock / Negative blocksGeometry Lock on every transform; Negative Block adapted to the medium (a diagram negates photorealism, not painterliness).
NotesAspect ratio and resolution, Regular vs Pro, source-export hygiene, staging advice.
Assumptions declaredEvery default applied that you did not explicitly confirm.
Flagged — for the architectDesign changes asked for in passing and deliberately left undone, one line each on why. Omitted if empty.

Three modes, and the mode decides everything downstream:

ModeTriggerNon-negotiable
GenerateText only, from scratchNothing material invented beyond your words or a declared default
TransformA source image that must keep its geometryGeometry Lock Block, with the specifics named (floor count, footprint, window positions)
CompositeSeveral images with different jobsEvery image numbered and given one role; one image owns the camera

Staging beats mega-prompts. Material + lighting + entourage in one prompt is the commonest cause of drift. One variable per pass, each stage using the previous output as its base.

What it will not do — by design

  • Redesign. "Add a canopy", "make the windows taller", "lose the substation" get flagged, not prompted. The image describes your design; changing it is your decision, made on the drawings.
  • Invent the design. No bronze mullions, no terrazzo floor, no adjectives you did not give. An invented material in a good render has a way of becoming the design.
  • Render compliance. No "Part M compliant entrance", no "safe means of escape" in a prompt — an image model neither knows nor checks regulations. Geometry gets described; the regulation gets named to consult and marked [to verify].
  • Produce a Verified View or AVR. Not this route, not any prompt. That is a surveyed methodology and a separate commission.
  • Leak the client. Client names, project codenames, addresses and figures are stripped from prompt text and filenames — the prompt goes to a third-party service. No web-searching the site unless you ask.
  • Prompt in a living architect's or photographer's style. Translated into the attributes you actually meant, and the swap is declared.
  • Render your project name onto the building. Rendered lettering is routinely misspelled, and a project name baked into a facade survives every crop; signage stays blank or generic.
  • Skip the interview silently. Either you get asked, or you get told which defaults were applied.
  • Take a sibling's job. Hero shot sets → hero-perspective-prompt-builder. Facade option studies → facade-maker. Four-figure site analysis → site-diagram-matrix-builder. Six-frame concept evolution → site-matrix-diagram-builder. Single images in any of those subjects stay here.

Work the output

  1. Read the Flagged list first — it is the list of things you now have to decide as an architect, not as a prompt.
  2. Check Assumptions before running anything; a wrong default costs a re-roll, an unnoticed one costs a client meeting.
  3. Re-export the source properly: 2× resolution, section planes, gizmos, sun-path widgets, watermarks and stamps hidden. Artefacts in, artefacts out.
  4. Run staged prompts in order, feeding each result in as the next base. Do not merge them because stage 1 looked good.
  5. Re-roll on Regular, final pass on Pro. Change one line between re-rolls so you learn what did it.
  6. Before the image leaves the office: count the storeys, count the windows, check the signage spelling, check nothing appeared that is not in the drawings.
  7. Caption it honestly — illustrative visualisation, not a verified representation — especially anything heading into a planning submission or public consultation at RIBA Stage 3+.

Remember: the prompt is only as honest as its assumption list. A short prompt with four declared defaults beats a lush one that quietly designed a canopy. Test drive: run it on the Marlowe Fields sample request and score against its defect key.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

nano-banana-prompt-builder

Turn a rough image idea — or a source image plus scribbled instructions — into a polished, reliable Nano Banana / Gemini image prompt for architectural visualisation: exteriors, interiors, masterplans, streetscapes and diagrams. Runs a short interview, then delivers a copy-paste prompt with geometry-lock and negative blocks, image-role labelling and staged edit chains. Use this WHENEVER someone wants to "write a Nano Banana prompt", "make a Gemini image prompt", "turn this Enscape/SketchUp/Rhino/Revit screenshot into a render", "restyle this render", "make this look photoreal", "add people to this image", or pastes a one-line idea expecting a proper prompt back. Also trigger on edit/transform requests against an uploaded image, and on prompts producing warped geometry. Do NOT use for hero shot sets (hero-perspective-prompt-builder), facade comparison studies (facade-maker), or site diagram sets (the two site matrix skills) — prompts here describe the architect's design and never redesign it.
