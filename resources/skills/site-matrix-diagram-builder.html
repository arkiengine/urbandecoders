Quick reference

How to run it.

Runs an interactive six-frame concept-evolution matrix on an empty site: boundary → context → circulation → programme → planting & ecology → final plan. Three directions (A/B/C) at every frame; you choose, it never picks for you. Ends with six coordinated image prompts, a shared legend and a board layout.

Not the four-figure analysis matrix (roads/buildings/greenery/radius) — that is the sibling site-diagram-matrix-builder, which reads what exists in one pass. This skill designs a concept in six chosen steps. Run them in that order on the same base if you want both.

Run it

Attach an empty-site aerial/screenshot (or a written site description), location notes and any style references, then ask:

Create a six-frame matrix diagram sequence for this site.
Primary programme: [e.g. community hub]. Priority: [e.g. biodiversity].

At each frame, reply A, B, C — or e.g. B but move the entry north (it restates that as B′ and confirms). Say recommend and I'll confirm to move faster; it still waits for your yes.

What it will not do — by design

  • Pick for you. Every frame waits for a choice; even "you decide" gets a recommendation you must confirm.
  • Invent geometry. No new roads, buildings, water or trees; reference images lend graphic tone, never terrain. Unclear boundaries stop the sequence with a question.
  • Make the brief fit. Before Frame 04 it sets the programme's ground area against your site area in plain numbers. If it doesn't close, you get the figures and the trade-offs — not a tidier frame.
  • Design outside the property line. Off-site ideas are flagged as ownership-dependent, not drawn.
  • Claim compliance. Planting is not BNG; blue-green arrows are not a drainage strategy. Adjacent standards are named to consult and marked [to verify], never quoted from memory.
  • Web-search your site or client unless you ask; no client names in filenames.
  • Generate images. It writes the prompts; generation is your separate step.

Work the output

  1. Check the Selected route — it is the record you defend at review.
  2. Read Checks before use first, not last: every unresolved ambiguity from the run lives there.
  3. Freeze the LOCKED BASE and STYLE blocks, then generate frames in order; regenerate any frame that drifts rather than adjusting later prompts to match the drift.
  4. Assemble the board in InDesign/Illustrator; the prompts are per-frame, not per-board.
  5. Redraw anything measurable over survey data (QGIS/Rhino/Revit) before it goes near a planning document — these are concept diagrams.

Remember: the sequence is only as honest as its base. If the boundary is guessed, six confident frames are six confident errors. Test drive: run it on the Fettler's Yard sample pack and score against its defect key.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

site-matrix-diagram-builder

Run an interactive SIX-frame urban site matrix — a concept-evolution sequence in plan view (boundary → context forces → circulation → programme zoning → planting and ecology → final concept plan) built frame by frame, offering three directions (A/B/C) at every frame and waiting for the user to choose before moving on, then delivering six coordinated image-generation prompts plus legend and board layout. Use this WHENEVER someone supplies an empty-site image, aerial, map screenshot or written site description and asks for a "six-frame matrix", "matrix diagram sequence", "concept evolution diagrams", "site strategy storyboard", "step-by-step site diagrams", "boundary-to-plan sequence", or wants to "develop the site concept frame by frame" or "build up the masterplan diagram in stages". Do NOT use for the single-shot FOUR-figure analysis matrix of existing layers — that is site-diagram-matrix-builder. Do NOT use for perspective renders, or to produce a technical masterplan or planning drawing.
