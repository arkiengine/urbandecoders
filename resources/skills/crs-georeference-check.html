Quick reference

How to run it.

Every dataset's CRS, datum, units, origin and epoch in one register: what each declares, where they disagree, and what the disagreement would look like on screen. Reconciles declarations. Never reprojects, never infers a CRS.

Run it

List or attach the datasets, and say what they are for:

These datasets won't line up. Build me a georeferencing register.
We're assembling a twin in Unreal over Cesium — do these share a frame?
The point cloud sits a metre above the survey. Which datum problem is this?
What do I need to ask the surveyor before we start modelling?

Say what the target platform is. The coordinate-magnitude consequences and the target frame options are written against it — and a GIS answer and an engine answer are frequently opposites.

The register

PartWhat it holds
InventoryEvery file: type, format, source, date, supplier.
Declaration tableCRS as declared · where the declaration lives · horizontal datum · vertical datum · units (H and V) · origin/offset · rotation · epoch · coordinate magnitude · confidence.
Agreement matrixPairwise: CRS, datum, units, origin — agree / differ / cannot tell.
Discrepancy listEach mismatch with the symptom it produces, so an observed misalignment traces back to a cause.
Undeclared & assumedDatasets with no CRS declared anywhere, held strictly apart from those that declare one.
Confirmation requestsOne-line questions the surveyor or publisher can answer in one line.
Target frame optionsTrade-offs stated, for you to choose. Never chosen for you.

Confidence: [declared] · [documented] · [stated] (a human said so — hearsay, however senior) · [undeclared] · [conflicting].

There is no [inferred] tag, deliberately. A CRS guessed from coordinate magnitude or from a location will be inherited as a fact by every downstream process. Not declared means [undeclared], and [undeclared] is a question.

The causes — short, boring, and always the same

  • Grid distance treated as ground distance. Small, systematic, grows with distance from the origin.
  • An undeclared vertical datum. Orthometric and ellipsoidal heights differ by tens of metres and both are called "height".
  • Units. Survey feet and international feet differ by two parts per million — invisible on a site, ruinous across a city.
  • A local site grid whose rotation and translation live in one consultant's head.
  • Datum realisation or epoch. The same nominal CRS at two epochs is not the same CRS where the ground moves.
  • A CRS assumed from the location rather than read from the file.

What it will not do — by design

  • Reproject, transform, shift or rewrite any file. It prescribes; you execute in GDAL/OGR, PROJ or the authoring tool with confirmed parameters.
  • Infer a CRS from coordinates, a place name, or what is usual in that country.
  • Supply EPSG definitions, datum shifts, grid files or transformation parameters from memory. A remembered parameter propagates silently into everything.
  • State a transformation's accuracy or how much error a datum mismatch adds.
  • Treat a matching CRS name as agreement where realisation or epoch may differ.
  • Round cannot tell to agree.
  • Choose the target frame.

Work the output

  1. Send the confirmation requests today. They are one-line questions precisely so they get one-line answers.
  2. Match your actual symptom to the discrepancy list before changing anything — the fix for a vertical datum offset and the fix for a grid-vs-ground error look nothing alike.
  3. Document any local grid or project offset as data, in a file that travels with the model. An offset in someone's authoring file is lost at handover.
  4. Decide the target frame deliberately, and record the decision. GIS wants true coordinates; a real-time engine wants small ones. You usually need both, with the transformation written down.
  5. Re-run whenever a new dataset arrives. One undeclared file poisons a federation that was previously consistent.
  6. Keep the register with the project data, not in an email. It is the only place the frame is written down.

Remember: the symptom is never the cause. A register that pairs every mismatch with the misalignment it produces turns three days of guessing into one question to the surveyor.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

crs-georeference-check

Reconcile the coordinate reference systems, units, origins and datums of every dataset in a project — survey, CAD, BIM, GIS vectors, rasters, point clouds, city models, engine scenes — into one register that states what each file declares, what it appears to be, where they disagree, and what must be confirmed before anything is overlaid. It never reprojects, transforms or rewrites a file, and never infers a CRS from coordinate values. Use this WHENEVER someone asks to "check the georeferencing", "why don't these line up", "what CRS is this in", "reconcile the survey with the GIS data", "our model is in the wrong place", "prepare these for Unreal/Cesium", "do these datasets share an origin", or is assembling a digital twin, masterplan basemap or federated model. Do NOT use it to perform a reprojection or transformation, to supply EPSG definitions, datum shifts or grid parameters from memory, to repair files, or to audit a single IFC in depth (ifc-model-audit).
