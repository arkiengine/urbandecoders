Quick reference

How to run it.

Resolves the cross-reference graph of a technical package: dangling callouts, orphan details, collisions, and junctions drawn nowhere. Audits references and coverage, never design. Draws nothing, renumbers nothing.

Run it

Attach the drawing set, and say what the package is for:

Audit the detail callouts across this package before we issue for construction.
Which details does nothing call up? And which callouts point nowhere?
We split the detail sheets last month. Did the references survive?
Which junctions on these elevations have no detail at all?

Say which consultant packages are not included. Otherwise every callout into a missing package reads as a failure and the count misleads you.

The three failures

  1. The dangling callout — a bubble pointing at a detail that does not exist or has moved. The contractor rings up. Twice.
  2. The orphan detail — drawn, checked, coordinated, called up by nothing. Usually it means a callout was deleted, so a junction is now undetailed.
  3. The undetailed junction — nobody drew it, nobody called it up, nobody noticed. An absence leaves no mark on a drawing set.

The first two are findable mechanically. The third is why the audit lists the conditions it can see and asks whether each is detailed, instead of only following the references that already exist.

What it will not do — by design

  • Judge whether a detail is correct, buildable, weathertight or compliant. References and coverage only.
  • Draw, sketch or describe a missing detail. A gap is a gap.
  • Renumber, re-reference or edit anything.
  • Quote a construction standard or performance figure from memory.
  • Report a junction as adequately detailed. It reports that a detail exists and is reached. Whether it resolves the junction is the author's call.
  • Count a missing consultant sheet as a dangling callout. Those are [verify manually], reported separately with a count.
  • Infer that an orphan detail is safe to delete. More often it means a callout was lost, which is the opposite problem.

Work the output

  1. Read the pattern findings before the individual ones. A convention that changed mid-package is one fix; fifty dangling callouts is fifty.
  2. Chase orphans as hard as dangling callouts — they point at undetailed junctions.
  3. Fix duplicates and collisions first. A contractor resolving an ambiguous reference may reach either detail, and will reach the cheaper one.
  4. Treat the junction coverage section as a conversation with the technical lead, not a defect list. It is marked [inferred] for a reason.
  5. Re-run after any sheet split or renumbering. That is precisely when the graph breaks and precisely when nobody checks.
  6. File the not-checked list; it names the consultant packages still outside the audit.

Remember: the audit proves the references resolve. Whether the detail they reach is any good is a technical review, and that is a different pair of eyes.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

detail-callout-audit

Audit detail and section callouts across a drawing set: every callout traced to the sheet it points to, every detail traced back to the drawings that call it up, with dangling callouts, orphan details, duplicated references, wrong-sheet pointers, scale and orientation mismatches, and junctions that are drawn nowhere. Returns a verdict-first report and a callout map; it never draws, renumbers or edits anything. Use this WHENEVER someone asks to "check the detail callouts", "do the section marks point to the right sheets", "which details are missing", "audit the callout references", "are there details nobody calls up", "check the drawing cross-references", or runs a pre-issue check on a technical package. Do NOT use it to judge whether a detail is correct, buildable or compliant, to draw a missing detail, to check specification coordination (spec-drawing-crosscheck), or to audit the register itself (drawing-register-audit).
