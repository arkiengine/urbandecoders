At a glance

What it takes, what you get.

It takes

A live model through the Revit MCP connector — or exported schedules and a warnings list

You get

Version and provenance, worksharing and link status, base point / survey point / internal origin with the distances between them, warnings grouped by type, levels, grids, worksets, phases and options, overridden dimensions, and element data down to ElementId, UniqueId and IFC GUID — ranked by what each breaks.

It will not

Edit, purge, save, sync or relinquish; infer a coordinate system from where the building appears to be; declare a model fit for purpose generically.

Design note

The real test is the next consultant model you receive, read before anyone trusts it. No worked example is bundled with this one yet; run it on live project material.

Quick reference

How to run it.

Forensic health-check of a Revit model before anyone coordinates, schedules, exports or builds a twin off it. Measures first, judges second, changes nothing. The model is evidence and a record; repair happens in the issuer's file, by the issuer.

Run it

Connect Revit (or attach the schedule and warnings exports) and say what the model is for:

Audit this Revit model — we're issuing it for coordination on Friday.
A consultant just sent this RVT. What can we trust?
Check the coordinates. We're exporting to IFC and importing into Unreal.
Model health check before we start the takeoff.
Is this model fit for a digital twin, or is it a visualisation model?

Naming the destination changes the audit materially: a model that is fine for plan production can be unusable for IFC, a takeoff or a game engine. Where a central file is involved, it is opened detached or read from a local copy — never synced, never relinquished.

The report

SectionWhat it holds
VerdictWhat the model is, what it can be used for as-is, what it can't without manual checks, and the single biggest problem. First, always.
ProvenanceRevit version saved in, workshared state (central / local / detached), issue or stage, file size, project units and rounding.
LinksRVT, IFC, CAD and point-cloud links with load status, attachment vs overlay, and anything reporting Not Found. Imported (not linked) CAD called out separately.
Geometry frameProject base point, survey point and internal origin with the distances between them, geometry beyond ~20 miles (32 km) of the origin, shared coordinates acquired or published and from which link, true vs project north, elevation base, site location or EPSG.
Model structureLevels and grids (duplicates, unpinned, levels with no views), worksets with counts and open state, phases and phase filters, design options and which is primary, groups and nesting depth, in-place families.
WarningsThe warnings list grouped by type with counts — several hundred of one kind is one finding, not several hundred.
Annotation integrityDimensions with overridden text, text notes hard-coding a number a parameter should hold, tags reporting blank or stale values, element-by-element graphic overrides, title-block scales disagreeing with the placed view.
Extractable dataInstances with family, type, Mark, level, room, key parameters, ElementId, UniqueId and IFC GUID — plus duplicate Marks, empty Marks, coincident instances and orphaned hosted elements.
Ranked risksHigh / Medium / Low / Info, each stating what it breaks downstream and what to do.
What was not checkedAlways present.

Tags: [measured] · [inferred] · [verify manually]. Every element-level finding carries its ElementId, so it can be found with Select by ID.

Coordinates — read this first, every time

An overridden dimension means nothing on that sheet can be trusted without checking the model. And geometry far from the internal origin is correct in survey terms and catastrophic in a single-precision engine — faces jitter, snapping fails, and it reads as a modelling error.

Establish in order: base point, survey point and internal origin and the distances between them · whether shared coordinates were acquired or published, and from which link · coordinate magnitude and its consequence for the stated destination · true north vs project north · whether a stated EPSG was read from the file or told to you by a human. Those last two are different, and the second is [verify manually].

What it will not do — by design

  • Touch the model. No transactions, no edits, no view overrides, no colour splash, no purge, no save, no sync with central.
  • Infer a coordinate system from where the building appears to be, or state what an EPSG code means from memory.
  • Fix anything. Remediation is prescribed, for the issuer to carry out in their own file.
  • Treat a blank parameter as zero or false. A missing Mark usually means nobody filled it, not that the element has none.
  • Judge design, clashes or compliance. Part M goes to part-m-revit-check; quantities go to revit-boq-takeoff.
  • Count warnings as severity. Volume and consequence are different things.
  • Declare a model "fit for purpose" generically. Fitness is per purpose, and the verdict names purposes.

Work the output

  1. Read the verdict. If a High says stop, stop before exporting, federating or measuring anything.
  2. Settle the geometry frame with the issuer before any IFC, GIS or engine import. Everything downstream inherits it and nothing downstream will warn you.
  3. Treat overridden dimensions as a drawing-wide finding, not a sheet-level one. Re-check the affected sheets against the model.
  4. Before building anything that joins on identity, confirm Marks are unique and capture UniqueId or IFC GUID — ElementIds do not survive a recreate or an upgrade.
  5. Send the ranked risks to the issuer as questions. They are defects in their model, not yours to patch downstream.
  6. File the not-checked list with the audit. It defines what is still owed before the model carries real weight.

Remember: the audit tests whether the model agrees with itself. Whether it agrees with the building is still a survey.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

revit-model-audit

'Audit a Revit model (live via the Revit MCP connector, or from exported schedules and warnings) for fitness for use: version and provenance, worksharing and links, base point / survey point / internal origin and shared coordinates, warnings by type, levels, grids, worksets, phases, options, rooms, overridden dimensions, and element data (Mark, ElementId, UniqueId, IFC GUID). Read-only; never edits, purges, saves or syncs. Returns a verdict-first report with ranked findings tagged [measured], [inferred] or [verify manually]. Use WHENEVER someone asks to "audit this Revit model", "model health check", "check this RVT", "model QA", "is this model fit for IFC / coordination / Unreal", "check coordinates in Revit", or receives a consultant model and asks what can be trusted. Do NOT use for DXF/DWG files, Part M reviews (part-m-revit-check) or quantity takeoffs (revit-boq-takeoff).'
