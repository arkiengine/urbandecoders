Two routes. Both end with Claude loading the skill by itself when your conversation matches.

A Claude app, Chat or Cowork

  1. Download gis-interactive-map.skill below.
  2. Open Claude, go to Settings → Capabilities → Skills and upload the file.
  3. Start a conversation and attach your material. The skill loads itself on a match.

B Claude Code, in your project

Unzip the package into your skills folder, then restart Claude Code.

mkdir -p .claude/skills && unzip gis-interactive-map.skill -d .claude/skills/

Use ~/.claude/skills/ instead to install it for every project.

What it takes, what you get.

It takes

You get

A single self-contained .html (Leaflet from CDN, data inlined): each dataset a labelled toggleable layer with legend, popups, scale bar and auto-fit, plus a data-integrity summary and an evidence-based read of what the layers show.

Quick reference

How to run it.

Turns your GeoJSON files into one self-contained interactive HTML map — Leaflet from CDN, all data inlined, layer toggles, legend, popups — plus a data-integrity report. Not a GIS — a trustworthy renderer of exactly what you supplied.

Run it

Attach one or more GeoJSON files (points, lines, polygons) and ask:

Build an interactive map of these datasets centred on [place / lat,long].
Map the site boundary, constraints and POIs as separate toggleable layers.
The flood layer is from the EA download; the rest is our own survey.   (state provenance!)
The points are dense — cluster them.                                   (large data)

Open the resulting .html by double-clicking — no install, no server. Base tiles need a connection; everything else is inside the file.

The deliverable

PartWhat it holds
The mapPan/zoom, scale bar, zoom buttons, OSM base with attribution.
Layer controlOne toggleable layer per dataset, expanded by default.
LegendFixed key: every layer, its colour, unverified layers marked.
PopupsEvery attribute of the clicked feature, HTML-escaped, [unnamed feature] where names are missing.
Info panelCollapsible: data summary, excluded features, [to verify] list, analysis, caveats — travels inside the file.
Chat reportData summary → map config → analysis → gaps & caveats.

Styling: colour-blind-safe palette (Okabe–Ito), one colour per dataset, semi-transparent polygon fills. Dashed outlines mean unverified data — the caveat survives a screenshot even when the legend doesn't.

What it will not do — by design

  • Fix your geometry. Projected coordinates (OSGB eastings/northings), swapped lat/lon, unclosed rings, null geometries are flagged and excluded — never silently corrected. Reproject in QGIS to EPSG:4326 and re-supply.
  • Draw constraints from memory. Flood zones, conservation areas, listings, TPOs only plot from a file you supply. Otherwise it names the source to get (EA Flood Map for Planning, NHLE, LPA policies map) and marks [to verify].
  • Declare compliance. "The site is outside Flood Zone 2" is a verdict against authoritative data, not a map caption. It shows what your layers show, labelled with their provenance, and declines the verdict.
  • Upgrade dubious provenance. If your description of a layer's source contradicts the file's own metadata, both are reported; the layer renders as unverified until resolved.
  • Invent attributes. Missing names show [unnamed feature]; missing fields stay missing and get flagged.
  • Web-search your site or client unless you ask; no client names in filenames.
  • Geoprocess. Buffers, catchments, joins belong in QGIS; map the result.

Work the output

  1. Read the excluded features list first — anything excluded is data you need to fix at source before the map is complete.
  2. Check every [to verify] item: fetch the authoritative dataset (EA / NHLE / LPA), re-export, re-run with real provenance stated.
  3. Toggle layers to sanity-check each dataset against the base map — a layer that "looks right" over OSM is your fastest gross-error check.
  4. Before circulating, confirm the info panel caveats are ones you can live with — the file travels without you attached.
  5. For the report figure, screenshot with the legend in frame; dashed layers are dashed for a reason.

Remember: the map is only as honest as its labelling — a sketched polygon in confident blue becomes "the flood zone" the moment it is forwarded. Test drive: run it on the Brindle Works sample (brief + three GeoJSONs) and score against brindle-works-defect-key.md.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

gis-interactive-map

Turn one or more GeoJSON files plus a target location into a single self-contained interactive HTML map (Leaflet from CDN, data inlined) — each dataset a labelled, toggleable layer with legend, popups, scale bar and auto-fit — plus a data-integrity summary and an evidence-based read of what the layers show. Use this WHENEVER someone supplies GeoJSON (site boundaries, constraints, points of interest, routes, survey points) and wants it "mapped", "on an interactive map", "as a Leaflet map", "as one HTML file I can email", "layers I can toggle", "plotted with a legend", or asks "put these datasets on a map of [place]", "visualise this GeoJSON", "make me a site context map". Also trigger for combining spatial datasets for a RIBA Stage 0–2 context study. Do NOT use for static print drawings, for geoprocessing such as buffers or catchments (do that in QGIS, then map it), or for sourcing constraint data — this skill plots supplied data and never generates flood zones or listings from memory.
