Quick reference

How to run it.

Turns a screenshot, photo or scan of a table into a faithful, editable .xlsx — every row and column in the printed order, values verbatim, unreadable cells flagged [check manually]. A copyist, not an editor: it transcribes the image's errors too, and logs them.

Run it

Attach the image (PNG / JPEG / screenshot / photo of a page) and ask:

Turn this door schedule into an editable spreadsheet.
Transcribe this screenshot as xlsx so I can edit it.
Here are three photos of one long schedule — transcribe them into one sheet.
This is a scan with no text layer; type it up faithfully.

The workbook

TabWhat it holds
TranscriptionThe table itself. Printed order, verbatim values, merged headers reproduced. [check manually] cells on amber fill.
Transcription notesSource & method (incl. the verification pass), cells to check, discrepancies observed not corrected — as live formulas — and conventions applied.

The flag — the one thing to look at first:

In the cellMeaning
A valueRead confidently off the image
[check manually] (amber)Illegible, obscured, cropped, or legible but ambiguous
External qualit… [check manually]Partly legible — fragment kept so you can find it
Blank / — / n/aThree different things. Transcribed as three different things.

"Fairly sure" is a flag, not a value. A guessed FD30 that should read FD60 looks identical to a real one once it is in a cell — and door schedules feed fire strategies.

Every run ends with a verification pass: the sheet is re-read against the image cell by cell, digits hardest, row count checked at every shading or page boundary. A transcription that has not been re-read is a draft, and the notes tab says whether it was.

What it will not do — by design

  • Correct the source. A total that doesn't sum, a duplicate reference, a gap in the numbering: transcribed as printed, logged with a formula that demonstrates it. The image is somebody's issued document.
  • Guess an illegible cell. However plausible the completion.
  • Sort, dedupe, renumber or reorder. Order is evidence — it may reveal the copy-paste error you need to see.
  • Normalise units or formats. 1.0 m in a millimetre column stays 1.0 m. FD30 and 30 min both stay. A silent conversion is the most expensive error here — and a correct one is still a provenance failure.
  • Fill blanks or resolve ditto marks. The source's choice of null marker is information.
  • Truncate. Every row. If the image is cropped, it flags the cut edge and asks for the rest rather than extrapolating.
  • Quote standards from memory. It may say a value is worth checking against Approved Document M or the project fire strategy, marked [to verify] — never the required figure, never an adjusted value.
  • Web-search the project or client, and no client names in filenames.

Work the output

  1. Filter the Transcription tab for amber — clear every [check manually] against the original before the sheet goes anywhere.
  2. Read Discrepancies observed on the notes tab next. Those are questions for whoever issued the schedule, not defects in the transcription.
  3. Decide the unit and format outliers yourself (1.0 m, 30 min) — then convert them deliberately, on a copy.
  4. Only then sort, filter or restructure. Do it downstream of the faithful copy, never on it.
  5. Exporting to Revit or a Grasshopper definition: regularise merged cells and mixed units after checking the flags, and keep the original tab as the audit trail.
  6. Multi-image jobs: check the seams first — duplicated or dropped rows at photo boundaries are the classic failure.

Remember: a bad photo should produce a largely amber sheet and a request for a better capture — that is the correct output, not a failure. The dangerous output is the confident-looking sheet quietly stitched together from part-guesses. Test drive: run it on the Cotterell Yard door schedule image and score against its defect key.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

screenshot-to-editable-table

Transcribe a screenshot, photo or scan of a table into a faithful, editable .xlsx — every row and column in the original order, cell values verbatim, unreadable cells flagged [check manually], with a transcription-notes tab and a mandatory second-pass verification against the image. Use this WHENEVER someone supplies an image of a table — schedule of accommodation, door or window schedule, ironmongery or finishes schedule, area schedule, room data extract, programme table, fee table, drawing-issue register, or a photographed page of any of these — and wants it "as a spreadsheet", "in Excel", "as xlsx", "editable", "so I can edit it", "typed up", or "converted from this screenshot/photo/scan". Also trigger on "turn this image into a table" or any request to avoid retyping a table shown in an image. Do NOT use for born-digital spreadsheets or CSVs, for charts with no underlying grid, or for text-layer PDFs — extract those with the pdf skill first; transcribe from pixels only when there is no text layer.
