Quick reference

How to run it.

Reconciles three sources that are supposed to agree — register, title block, filename — and reports where they do not. Read-only. Never renames, renumbers or re-issues anything.

Run it

Attach the register and the drawing files (or a listing), and say what the issue is for:

Audit this register against the folder before we issue for tender.
Do the revisions match the title blocks? We've had a claim on a superseded sheet.
Check this issue — something's missing and I can't see what.
We've inherited this set. What's the numbering convention and where does it break?

The issue purpose governs which findings are High. A "Preliminary" status is unremarkable in a coordination issue and serious in a construction issue.

The report

SectionWhat it holds
VerdictSafe to send? The single biggest problem, and what would have to change. First, always.
ReconciliationOne row per drawing, three columns of truth: Register · Title block · Filename.
Missing & orphansOn the register but absent; present but unlisted — including superseded sheets dragged back in.
Revision integrityMismatches, regressions (a lower rev issued after a higher one), revisions with no register entry.
NumberingConvention inferred from the set, every departure, and sequence gaps split into withdrawn / unexplained / reused.
Status & suitabilityCodes present, consistency with each other and with the issue purpose.
Ranked findingsHigh / Medium / Low / Info, each naming what it breaks.
What was not checkedAlways present.

Evidence tags: [register] · [title block] · [filename] · [inferred] · [verify manually].

Where the three sources disagree the report never picks a winner. It quotes all three and marks the row conflict. Which is correct is a question about what was actually drawn.

The findings that cost money

  • Revision regression — a lower revision issued after a higher one.
  • A superseded sheet still in the issue folder — the number looks right, so nobody checks. A contractor building to it has a claim, evidenced by your own issue sheet.
  • A number reused for a different drawing. Always High.
  • Systematic drift — every title block one revision behind the register. Reported as a pattern, which is a different problem from scattered errors.

What it will not do — by design

  • Modify anything. No renaming, renumbering, editing or re-issuing. An annotated register adds columns and leaves originals untouched.
  • Check drawing content. Whether the drawing is right, coordinated or buildable is outside this audit entirely.
  • Fill a title-block field from the register. That circularity would destroy the only independent check the audit has.
  • State what a suitability or status code means from memory. Practices and protocols use the same letters differently.
  • Assume a numbering standard. It infers the convention in use, states it, then tests the set against it.
  • Declare a set complete. It can say the register and the files agree. That is a much smaller claim and is phrased as one.

Work the output

  1. Read the verdict. If a High says do not issue, stop the issue before reading further.
  2. Hunt the orphans first — a stale superseded sheet in the folder is the finding most likely to end up in a dispute.
  3. Resolve three-way conflicts with the drawing author, not in the register. The register is the record of what you sent, not the place to make it look right.
  4. Decide sequence gaps deliberately: withdraw formally or reuse the number never.
  5. Define your suitability codes somewhere the audit can read them, and the status findings sharpen from "code present" to "code wrong".
  6. Re-run immediately before issue, not the day before. Registers drift in hours.

Remember: this audit tests whether the paperwork agrees with itself. Whether the drawings are any good is a different review, and no register audit will ever catch a wrong detail.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

drawing-register-audit

Audit a drawing register or issue sheet against the files actually present: missing drawings, files not on the register, revision mismatches between register, title block and filename, numbering convention breaks, gaps in the number sequence, superseded sheets still in the issue, and status/suitability codes that contradict the issue purpose. Returns a verdict-first report; it never renames, renumbers or re-issues anything. Use this WHENEVER someone asks to "check the drawing register", "audit this issue", "is this set complete", "do the revisions match", "what's missing from this issue", "check the drawing numbers", "reconcile the register against the folder", or before any formal issue to a client, contractor or authority. Do NOT use it to check drawing content or quality, to cross-check drawings against a specification (spec-drawing-crosscheck), to transcribe a register from an image (screenshot-to-editable-table), or to modify files.
