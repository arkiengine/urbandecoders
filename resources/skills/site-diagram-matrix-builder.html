Quick reference

How to run it.

Turns one site into four coordinated image prompts — roads, buildings, greenery, radius circles — sharing a single locked boundary, crop, orientation and theme, ready for a 2 × 2 analysis board. An as-found reading of the site, not a design.

Not the six-frame concept sequence (boundary → context → circulation → programme → planting → final plan) — that is the sibling site-matrix-diagram-builder. Four panels, one moment, four layers here; six panels, one concept, six moments there. For prompt craft outside this matrix, use nano-banana-prompt-builder.

Run it

Attach the aerial/map screenshot, plan or GeoJSON boundary (or a written site description if that is all you have) and ask:

Build me a four-figure site diagram matrix for this site.
Dark theme, 2×2 board, rings from the station entrance.
Same set again in monochrome for the printed A1.        (theme re-encode)
Rural site — propose the layer set before you write anything.

It will come back with questions before it writes prompts. The theme, the ring centre and the ring values are the ones it will not start without.

The deliverable

PartWhat it holds
Intake recordWhat you confirmed — theme, centre, radii, ratio. The provenance of every number below.
Site summaryBoundary, orientation and each layer, tagged Stated / Inferred / Unresolved.
Theme encodingThe preset as actual hexes and line rules — not mood words.
Matrix overviewOne line per panel: what that figure is for.
Shared consistency blockThe spine. One block, repeated verbatim in all four prompts.
Figures 01–04Four copy-paste prompts, one dominant layer each, others ghosted.
Legend & 2 × 2 layoutCombined key, panel order, titles, where the legend strip sits.
Checks + open queriesBoundary fidelity, orientation status, [to verify] distances, logged contradictions.

The four figures: 01 Roads connectivity · 02 Buildings grain and figure–ground · 03 Greenery existing green infrastructure · 04 Radius circles catchment from a confirmed centre. Non-urban sites get an adapted set, proposed and confirmed first.

The shared block is not boilerplate. Image models have no memory between generations — that block is the only thing making four separate images sit on one board.

What it will not do — by design

  • Invent geometry. No plausible extra street, no completing a block the crop cuts off, no trees at guessed positions. Unknown means omitted and logged.
  • Assume a radius, a centre or a catchment. Defaults are proposed; nothing is drawn until you confirm.
  • Call a circle a walkshed. A radius is straight-line; a walkshed follows the network and is cut by rail, water and severance. "5 minutes' walk" is not a distance until you state a speed and a source.
  • Quote policy distances from memory. The document is named for you to check and the figure carries [to verify].
  • Draw proposals as existing. Unbuilt blocks and unagreed accesses are dashed and labelled proposed, or absent.
  • Resolve contradictions. Both versions logged; where a figure must be issued meanwhile, the image governs over the notes and says so.
  • Drift to imagery. Flat plan-view diagrams; every prompt carries anti-photoreal negatives.
  • Design. No re-parcelling, no suggested routes, no "the site wants a green spine".
  • Web-search or geolocate your site unless you ask; no client names or addresses in filenames.
  • Generate the images. It writes the prompts; generation is your step.

Work the output

  1. Read Checks + open queries first. It tells you what the four panels can and cannot yet claim.
  2. Freeze the shared consistency block before generating anything. If you edit it, regenerate all four — a board with one drifted panel is worse than a board with none.
  3. Generate 01 → 04 in order. If a panel drifts, regenerate it; do not bend the other three to match the drift.
  4. Check each image against the source before it goes on a board — count the blocks, follow the roads, look for streets the model invented.
  5. Rings: confirm the centre is where you said and each label carries its centre, not just its distance.
  6. Assemble in InDesign/Figma/PowerPoint per the 2 × 2 note. Anything measurable gets redrawn over QGIS/Rhino data before it goes near a planning document.

Remember: these are analysis diagrams, not survey drawings, and a crisp labelled circle outlives every caveat you said out loud. Test drive: run it on the Cinderhill Sidings sample pack and score against its defect key.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

site-diagram-matrix-builder

Turn a chosen site (aerial screenshot, plan, map extract, or written site description) into FOUR coordinated site-diagram image prompts — roads, buildings, greenery, and radius/influence circles — sharing one locked boundary, orientation, crop and graphic theme, ready for a 2×2 site-analysis board. Use this WHENEVER an architect or urban designer asks for a "four-figure site diagram matrix", "site analysis diagrams", "layer diagrams", "figure-ground plus roads plus green plus catchment set", "diagram matrix for my analysis board", "coordinated site diagrams", or wants separate roads / buildings / greenery / radius diagrams that match visually. Also trigger on "one diagram per urban layer". Do NOT use for a SIX-frame interactive concept-evolution sequence — use site-matrix-diagram-builder instead. Do NOT use for hero renders (hero-perspective-prompt-builder), general prompting (nano-banana-prompt-builder), or real-data maps (gis-interactive-map). It diagrams the site as it is; it never proposes.
