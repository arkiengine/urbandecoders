Quick reference

How to run it.

Forensic health-check of an IFC before anyone federates, schedules or hands it downstream. Measures first, judges second, changes nothing. The file is a deliverable and a record; repair happens in the issuer's authoring model.

Run it

Attach the .ifc and say what it is for:

Audit this IFC — we're federating it with the structural model next week.
Can we schedule doors and windows off this file?
Check the georeferencing. We're importing it into Unreal over a GIS basemap.
This came from a consultant we haven't worked with. What can we trust?
Compare these two exports — did the GlobalIds survive?

Naming the destination changes the audit materially: a file that is fine for visual coordination can be unusable for a twin. Supplying two versions enables the GlobalId stability check — the single most valuable test for any twin workflow.

Georeferencing — read this first, every time

A present-but-empty map conversion is worse than none, because tools treat it as authoritative. And large true coordinates are correct in GIS and catastrophic in engines working in single precision — geometry jitters, snapping fails, and it reads as a modelling error.

Establish in order: the method and whether it is complete · origin, base point and survey point relationships · coordinate magnitude and its consequence for the named destination · units and length precision · whether a stated CRS is declared in the file or was told to you by a human (those are different, and the second is [verify manually]).

What it will not do — by design

  • Touch the file. No repair, re-export or re-save. Remediation is prescribed, in the issuer's authoring tool.
  • Assume or infer a CRS, or state what an EPSG code means from memory.
  • Convert units or coordinates.
  • Present IFC base quantities as a reliable takeoff. What a quantity includes is exporter-dependent.
  • Judge design, coordination or compliance. Clashes and code are outside this audit entirely.
  • Treat an absent property as zero or false. A blank schedule cell usually means the exporter never wrote the property.
  • Assert GlobalId stability from a single export.
  • Declare a model "fit for purpose" generically. Fitness is per purpose, and the verdict names purposes.

Work the output

  1. Read the verdict. If a High says stop, stop before importing anything.
  2. Settle georeferencing with the issuer before any twin, GIS or engine import. Everything downstream inherits it and nothing downstream will warn you.
  3. Use fill rates, not presence, to decide whether you can schedule. "412 of 1,284 doors carry the property" is a decision; "has property sets" is not.
  4. Ask for a second export and re-run the identity check before building anything that joins on GlobalId.
  5. Send the ranked risks to the issuer as questions — they are their defects to fix in their model, not yours to patch in the export.
  6. File the not-checked list with the audit. It defines what is still owed before the model carries real weight.

Remember: the audit tests the file's internal honesty, not the building. A clean audit means the model agrees with itself — whether it agrees with reality is still a survey.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

ifc-model-audit

Forensic audit of an IFC file before anyone federates, schedules or hands it downstream: schema and exporter provenance, georeferencing and units, spatial containment, classification and property set coverage, GlobalId stability and duplication, type-vs-occurrence discipline, quantity reliability, and geometry representation — reported verdict-first with every claim tagged [measured], [inferred] or [verify manually]. The file is evidence and is never modified. Use this WHENEVER someone supplies an .ifc and asks to "audit this IFC", "can we trust this model", "is this IFC fit for coordination", "why don't the quantities match", "check the georeferencing", "will this federate", "can we schedule off this", or before importing an IFC into a twin, a viewer, a game engine or a takeoff. Do NOT use it to modify, repair or re-export IFC, to audit a native .rvt (revit-model-audit), to check design quality or regulatory compliance, or to convert geometry.
