At a glance

What it takes, what you get.

It takes

One or two images of the object, at least one real dimension or a data sheet, and a destination folder

You get

A family spec you confirm before anything is built, then the family itself: parameters, planes, locked geometry, materials and subcategories — plus a flex table proving every parameter moves. Balustrades become a Railing type you draw as a line; rows of objects become a line-based repeater.

It will not

Import a mesh, DWG or AI-generated model; claim parametric without a passing flex test; touch your project without a yes; certify guarding or make a manufacturer claim.

Design note

A product photo and one known dimension is all it needs to run end to end. No worked example is bundled with this one yet; run it on live project material.

Quick reference

How to run it.

A photo of an object becomes a native, parametric, flex-tested Revit family — forms locked to reference planes and driven by named parameters. Never an imported mesh. It proposes the spec, waits for your yes, builds, then proves the parameters work before calling anything parametric.

Run it

Attach the image, give one real dimension, and say where the .rfa goes:

Make this sofa into a Revit family. Overall width is 2100.
Family from this photo — it's a bollard, 1100 high, and they repeat at 1500.
Turn this balustrade into a railing type. Top rail at 1100.
Parametric family from this image. I only have the front view.
No Revit connection here — give me the script to run in pyRevit.

A straight-on front or side view is worth more than a perspective hero shot; a second view is asked for when depth or the back is hidden. Without a dimension or a data sheet it proceeds on stated defaults, every one tagged [assumed default].

Why a balustrade becomes a Railing type, not a wall. A railing type is what gives you "sketch a line and it repeats at increments": a path, a baluster pattern at a set spacing, start, end and corner posts, justification and excess-length fill. It follows stairs and ramps, schedules as Railings and exports as IfcRailing. A curtain-wall balustrade draws like a wall, exports as IfcCurtainWall and cannot host to stairs — offered only if you explicitly want wall behaviour.

The spec it proposes — then stops

Nothing is built until you confirm: route, template and family name · the parameter table (name, type or instance, group, default, formula, flex range, source tag — sizes and materials as type parameters, derived values as formulas) · the geometry recipe, each component with its primitive and the reference planes it locks to · types or type-catalogue rows · for railings, the RailingType spec with heights, baluster pattern, posts, rail profiles and justification · and what the image could not tell you, each with the default chosen.

Dimension tags: [user given] · [from data sheet] · [estimated from image] · [assumed default].

The flex test

"Fully editable" is a claim, and it has to be proven. Nothing is called parametric until this passes.

Every driving parameter is set to its minimum, default and maximum and committed, and the result recorded: ok · constraint failure with Revit's own message · or geometry that didn't follow, caught by checking the bounding box against the parameter. Arrays flex to their minimum count; every catalogue row is loaded. Failures are fixed and re-run, and reported rather than hidden. Railings get a test run in a scratch project — a straight run, a 90° corner and an arc — to check post placement, end spacing and rail joins.

What it will not do — by design

  • Import geometry. No DWG, SAT, OBJ or mesh, and no AI-generated 3D model wrapped in a family. They are heavy, cannot flex, and break schedules and IFC.
  • Build before you confirm the spec.
  • Claim "fully parametric" without a passing flex test.
  • Touch your project. Families are built in new documents and tested in a scratch project. Loading into your model or creating types there needs an explicit yes. Nothing is overwritten — an existing file gets a version suffix and you are told.
  • Read size off an image. An image is evidence of shape and proportion only.
  • Make a manufacturer claim. A recognisable product is named generically; Manufacturer, Model and URL stay blank unless you supply them. Geometry is a lookalike at LOD 200–300.
  • Certify guarding. Balustrade heights, gaps and loads are parameters with defaults tagged [verify against Part K / project spec].
  • Model buildings, or audit models — that is revit-model-audit.

Work the output

  1. Read the "what the image could not tell you" list before the geometry. Those are the decisions you are inheriting.
  2. Check the flex-test table row by row. A failure there is a family that will break the first time somebody edits a type.
  3. Open the .rfa and flex it yourself once, in your own units. Two minutes.
  4. Fill Assembly Code and Keynote — left blank [to fill] on purpose, so revit-boq-takeoff can map the family later.
  5. For railings, bring the type into your project with Transfer Project Standards from the scratch .rvt.
  6. For balustrades and guards, check height and gaps against Part K and the project spec before anybody draws with it.

Remember: with no live connection it hands you the spec plus a runnable IronPython script per family — and says plainly that the scripts have not been run.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

image-to-revit-family

Turn a photo or image of an object (sofa, chair, table, light, planter, bollard, balustrade, railing, glass guard) into a native, parametric, flex-tested Revit family built through the Revit MCP connector, or an IronPython script when no connection exists. Loose objects become loadable families with reference planes, labelled dimensions, material and size parameters and a type catalogue. Balustrades become a Railing type with baluster, post, panel and rail-profile families, so the user sketches a line and balusters repeat at the set spacing. Rows of repeating objects become a line-based array family. Proposes a spec from the image and builds only after the user confirms. Use WHENEVER someone says "make this into a Revit family", "model this sofa in Revit", "family from this photo", "turn this balustrade into a railing type", "parametric family from this image", or uploads a product photo and wants it in Revit. Do NOT use for whole buildings, mesh or photogrammetry import, or model audits (revit-model-audit).
