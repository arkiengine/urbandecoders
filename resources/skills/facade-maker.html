Quick reference

How to run it.

Turns a facade design intent pack + a base image into a coordinated set of image-model prompts — material, bay, proportion and elevation-to-render studies — sharing one locked consistency block so the outputs are genuinely comparable. Not an image generator, and not a design adviser — a study instrument.

Run it

Attach the intent pack (.md / .docx / .pdf) and the base image (or a clean CAD elevation export), then ask:

Run a facade material study from this pack and base render.
Write a bay study for the typical upper-floor bay — coursing and joint options.
Proportion study: the two window-to-wall ratios stated in section 3.
Turn this Revit elevation export into a rendered elevation, then run the cladding options against it.
Option A-02 came out too orange — revise that prompt only.        (iteration)
All five are generated and approved — specify the comparison board.

The prompt-set document

PartWhat it holds
HeaderPack name/rev/date, base image identity, RIBA stage if stated, "design study — not a Verified View" statement.
Consistency blockOne paragraph, verbatim in every prompt: camera, geometry, openings, glazing, context, sky, light, style register. One lock per study — two locks in one study = incomparability.
Variant promptsA-01, A-02… one stated variable each, copy-paste runnable, every one captioned Option for review — no preference implied.
Run instructionsSame base image every run; geometry drift warnings; finishes that commonly need an iteration round.
Open questionsEvery conflict, [not stated], arithmetic mismatch and [to verify] claim, keyed to the prompts it affects. Blocking questions mark their prompt blocked.
Iteration logOne row per revision: what the architect reported, what changed, whether the lock was touched.

Study types: A material (swap one finish, all else locked) · B bay (one bay, close range — crop route preferred) · C proportion (geometry varies, strictest lock — models drift here) · D elevation-to-render (CAD linework → rendered elevation, then variants run on the render).

What it will not do — by design

  • Invent design content. No materials, colours, modules, joint patterns or adjectives the pack didn't state. "Slender" and "weathered" are design decisions when invented; unstated values stay [not stated] and become questions.
  • Recommend, rank or shortlist. "Pick the best two" gets review criteria back, not a verdict. Option order follows the pack, never predicted quality.
  • Vary two things at once. A coupled variant (material and reveal depth) is held until the architect decides to study it coupled or split.
  • Resolve pack conflicts silently. Two stated bay widths are both logged; if a prompt proceeds, it says which wording it used and why.
  • Carry performance claims into prompts. "A2-rated" cladding becomes "timber-effect boards" in the prompt and a [to verify] line in the questions — fire classifications, U-values and policy compliance are never quoted from memory and never rendered.
  • Present AI images as evidence. Not Verified Views/AVRs, not planning drawings. Verified views are a separate surveyed methodology.
  • Claim images exist. No boards, no described results, until you confirm generation.
  • Web-search the client or site unless you ask; no client names in filenames.

Work the output

  1. Read the open questions before generating anything — a blocked prompt means the pack, not the prompt, needs fixing first.
  2. Run every prompt on the same base image in the same tool (default phrasing targets Nano Banana / Gemini image editing).
  3. Sanity-check each output against the drawings — count windows, storeys, coursing — before anyone falls in love with one.
  4. Report failures verbatim ("brick too orange", "it moved the windows"); revisions touch one prompt at a time, and a touched lock means earlier images are no longer comparable.
  5. Confirm which images exist, then ask for the comparison board spec (e.g. A4 portrait 2×3, base + five, titled cells).
  6. Selection is yours: use the review-criteria list, decide, then carry the chosen option into Stage 3 iteration with the same lock discipline.

Remember: the study is only as comparable as its lock, and only as honest as its provenance — a two-option set with eight open questions is a better output than ten options of invented materials. Test drive: run it on the Weaver's Yard sample intent pack and score against its defect key.

Triggering

When Claude reaches for it.

This is the description Claude itself reads to decide whether the skill applies. It is worth knowing, because it tells you exactly how to phrase the ask — and what the skill will decline.

facade-maker

Turn a facade design intent pack (bay dimensions, material palette, precedents, constraints) plus a base image into a coordinated set of image-generation prompts for facade studies — material variants, bay and proportion studies, elevation-to-render — every prompt sharing one consistency block so outputs are comparable, and every variant labelled an option to review, never a recommendation. Use this WHENEVER an architect wants to iterate a facade with an image model: "run a facade material study", "swap the cladding on this render", "test brick vs fibre cement", "bay study", "proportion variants", "try different window-to-wall ratios", "turn this elevation into a render", "facade options for the client meeting", "cladding options board". Do NOT use for general archviz prompting (nano-banana-prompt-builder), for hero/marketing money shots (hero-perspective-prompt-builder), or for interiors, masterplans and aerials — this skill owns facade studies only, and never picks a winning option.
